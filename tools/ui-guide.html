01 · color system

Color

A near-black ground, one warm body ink, one global amber, and nine medium signal colors. Every color has a full-strength signal use and a 25%-opacity dim variant for borders, dividers, and washes.

Solid canvas rule (non-negotiable): every website page uses one opaque var(--color-bg) page canvas. Never put a gradient, image, transparency, grain/noise, color wash, or full-viewport pseudo-element on html, body, or the root page shell unless the page has an explicit approved exception. Atmospheric treatments belong inside contained media or components.
Structural rule (non-negotiable): every visible public-page border, divider, frame, timeline rail, and graph stroke is 5px. Use no rule when separation is unnecessary; do not introduce 1px hairlines. Record and card grids use a modest 12–16px gutter so each framed item has room to read.
Archive surface: use #B87A32 as the Archive's reading ink and set all Archive body copy in uppercase. Archive hero titles use var(--color-archive) so they match the Archive node, and hero framing uses the same node token.
Adjust these live: hit 🎨 Edit colors & type in the toolbar (or the button below) to open the global editor — tune the palette, shared text colors, body copy, hero descriptors, eyebrows, breadcrumbs, footers, metadata, and every medium signal ramp, then write the result back into tokens.css. The editor is hidden when you export the PDF.

Medium signal colors & ramps

Each swatch is a three-stop ramp — dark (signal mixed toward black), the signal color, and bright (mixed toward white) — with the 25% dim variant as the thin strip beneath. Hex labels read dark · signal · bright. These swatches stay in sync with the live tuner.

Medium signal colors
The medium accent rule (non-negotiable): every medium page must use its own medium color as the primary accent. Never use global amber #FCB867 as the primary signal color on a medium page. Set --venture-color in the page's :root: 
/* in the page's CSS */
:root {
  --venture-color: var(--color-tattooing); /* this medium's token */
}

Then use var(--venture-color) for: filter-chip active states (dot + underline), section labels and kicker text, status indicators, active UI states, and hover border colors on cards and interactive elements. The property is still named --venture-color for legacy compatibility — keep the name.

Source-label badge rule: when a small label names a product source or medium, make the source color a solid badge fill and choose readable ink on top. Do not rely on 10px colored text at reduced opacity for blue, red, or other dark signals on phones.

02 · typography

Typography

Two voices anchor the default system: Inter 900 for anything declarative and Georgia for everything that reads. Public hero titles share one role with two scales: medium landings use the large --type-hero-* clamps, while supporting pages use the smaller --type-supporting-hero-* clamps. Both variants use the same tracking values at every breakpoint. The global editor controls those responsive scales alongside body copy, hero descriptors, eyebrows, breadcrumbs, footers, and metadata.

Identity bands · .brand-band / .artist-band

Brand and artist profiles are owned entirely by css/identity-bands.css; pages provide content and a documented modifier, never local band rules. Every identity band uses the same two-column anatomy above 768px. Artist portraits retain the shared 4:5 media footprint; brand logos use a mark-fitted first column derived from the artwork's real aspect ratio, preserving logo height without reserving an oversized invisible box. Brand-band titles and rendered logos use global amber --color-accent; the source logo assets retain the Legend symbol color #6D3D15 for their other contexts. Logos align to the content-facing edge and link directly to their managed Identity record in /about/legend/. Brand bands use an 8px desktop inline inset and a 12px structural gutter, with the action aligned to the start of the title and descriptor column. Below 768px, a brand mark spans the title and descriptor rows so its rendered height matches that combined text stack; the action row then spans both columns below them. Artist bands use a larger responsive portrait track, cap the title measure at 200px, and bottom-align the eyebrow/title lockup with the portrait so longer names can form a deliberate three-line stack. Both use an 8px leading inset, 16px trailing inset, and a tight 4px media-to-content gap. A .band-portrait-trigger may open a full-size .band-image-dialog; it follows the Art and Tattoo image-viewer convention with a full-viewport dark overlay, an unframed image constrained to 92vw × 92vh, and the Special Project media viewer's bordered uppercase Close control fixed near the top-right. The Close control locks its tracking and line-height so its desktop and mobile appearance remains identical instead of inheriting responsive body typography. It must remain keyboard operable and support its close control, Escape, backdrop click, focus return, and scroll restoration through js/identity-band-lightbox.js. Band actions remain filled with their medium color by default, while links into the About node use a transparent fill with muted Construct amber --color-accent-dim for their 5px border and text at rest, becoming full --color-accent on hover or keyboard focus. Tattoo House is the brand reference: every brand title uses clamp(34px,8vw,112px), and every description uses 14px Georgia in rgba(252,184,103,.64). Proper brand names such as ThoughtPuppet remain unbroken and use a container-relative size guard to fit their actual content column.

Edit checklist

  • Solid page canvas: html, body, and the root shell resolve to opaque var(--color-bg). Keep gradients, texture, and imagery inside bounded components.
  • Shared page anatomy: align the closest sibling page's header/navigation, breadcrumb, hero, shell width and rhythm, footer, and shared script order before adding page-specific styling.
  • Hero variant: every primary hero uses .site-hero plus exactly one variant. Use .site-hero--landing only for the six medium landings at /about/, /art/, /merch/, /tattoos/, /events/, and /archive/. Use .site-hero--supporting everywhere else.
  • Hero title: apply .hero-title to the primary title and load css/hero.css after css/site-typography.css. Page CSS owns outer composition, not title color, font, scale, tracking, leading, wrapping, or breakpoints. Landing and supporting titles share the supporting-title tracking values; only their scale and leading differ. Medium-landing titles use a fluid mobile clamp that grows with available width and tops out at 112px. The shared transition utility measures each landing title against its actual column and only reduces the CSS target when necessary, keeping long medium names intact without clipping or character-level breaks.
  • Hero descriptor: use .hero-descriptor for the first concise copy paired with the hero title. css/hero.css supplies the shared Merch/Tattoo treatment: Georgia serif, 12px, uppercase, 0.22em tracking, 1.6 leading, rgba(252, 184, 103, 0.55) color, left alignment, a 380px desktop measure, and 16px bottom padding. At tablet and mobile widths, every medium-landing hero stacks into one full-width column and its descriptor expands across that column. Supporting-page descriptors retain the 380px measure. Additional explanatory paragraphs remain body copy.
  • Identity bands: use css/identity-bands.css and the explicit .band-* roles for brand and artist profiles. Keep schedules, hours, and other operational information in sibling components such as .walkin-section, never inside the identity band.
  • Root-relative paths only (/css/…, /art/) — the site deploys at the domain root on Cloudflare Workers. No build step; static files + _worker.js.
  • data-venture set correctly on <body> — it drives dot nav highlight, breadcrumb labels, and footer links.
  • --venture-color set to this medium's token — never global amber on a medium page.
  • Use token steps for size, spacing, easing — don't freestyle values between steps.
  • Ecosystem-first: every page points to at least one other medium — a related-medium band, source lineage, or a quiet next action (inquire, claim, read, attend, collect, listen, revisit, enter the archive). Subtle; discovery, not promotion.
  • Mobile pass: collapse grids with minmax(0,1fr); verify at 390px; confirm css/hero.css neutralizes editor-injected title sizing through inherited hero styles.
  • Forms: ordinary visitor data-entry uses .public-form and the interfaces owned by css/forms.css. Tattoo/acquisition submissions POST multipart/form-data to /api/submissions and include the _gotcha honeypot.
  • Archive catalogue: keep the permanent base ID read-only; derive the current public condition from a real published/public state; use Roman state labels, stable in-dossier anchors, eligible lead materials, and 5px evolution rails. Adaptive documentation augments canonical title, date, medium, people, organizations, states, and digital-asset permissions rather than duplicating them. Comparison state belongs in the shareable /archive/compare/ URL.
  • Archive Blackboards: /archive/blackboards/ is a supporting Archive lens, not a replacement catalogue. Use the shared supporting hero, opaque Archive canvas, 5px scan frames and section dividers, 16px card gutters, newest-first complete boards, one-column mobile layout, and a keyboard-operable native dialog for scan zoom. Fragments are deduplicated by Digital asset and retain every “Source for” record link.
  • Never push — commits are fine; the user always pushes manually. Work directly on main in the main repo (no worktrees).

Language

Legacy technical identifiers keep the old venture name — body[data-venture], --venture-color, Shopify venture: tags. Leave them unless doing a dedicated migration.

Generous language rule

Describe what the work invites, offers, carries, and opens toward. Preferred phrasing: "best for," "drawn toward," "built for," "good entry point," "opens into." Warm boundaries that explain the path forward; process language that helps visitors enter well. Reserve hard boundary phrasing for operational clarity (booking status, legal, confirmations) — and keep even that plain and generous.

Ecosystem-first principle

Every page is a medium in a living ecosystem. When editing any page ask: what is its primary action? Which other mediums should it point toward? Is the connection conceptual, commercial, archival, experiential, or biographical? Connections should feel like discovery — quiet paths, traces, source threads, optional doors — never banner cross-promotion. A conversion page stays focused but carries at least one subtle reminder of the wider construct.

Connections to Other Domains / Archive rule: the shared connection area is an actual titled section using the public section-title role and a responsive grid of compact vertical cards. When a canonical entity has a published public Archive dossier, the section ends with an Archive group parallel to “Source for” and “Uses symbol,” containing a card titled “Explore the record of this work.” Its media frame contains a bold serif capital A. Every other connection card uses the connected item’s canonical image; externally managed merchandise resolves its product photography from Shopify. Connection-card metadata names only the item type and its node; publication state is not displayed. The Archive card is supplied by /api/connections/:id and rendered by js/construct-connections.js with css/construct-connections.css; it is a companion view of the same entity, so it is not modeled as a relationship edge or added to Graph view.

Known gotchas

GotchaDetail
Editor-injected hero spansAll public heroes load css/hero.css, which makes nested title and descriptor spans inherit the shared role at every viewport. Do not restore page-local inline color, font size, tracking, leading, or case styles.
Bare 1fr mobile collapse1fr can't shrink below child min-content. Always minmax(0, 1fr) in collapse rules. When auditing a cut-off page, check the computed grid track width first.
data-venture is legacyAttribute and --venture-color keep the old name on purpose. Renaming breaks construct-nav, wayfinding, and Shopify tag mapping.
Two .media-grid definitionscss/media.css defines the card grid (auto-fill 260px); css/venture-pages.css also defines a 2-up .media-grid for media panels. Don't load both on one page without checking which wins.
Hidden pagesHiding/showing is done through /tools/page-visibility.html, which edits _worker.js and moves files to .hidden-pages/. Don't hand-move page files.
Token synccss/tokens.css is the palette source. The guide, homepage canvas, and injected dot nav read those variables when served locally. Refresh open pages after saving; use a literal search only for older one-off hardcoded surfaces.
UI Guide working URLUse http://localhost:4173/tools/ui-guide.html as the canonical working surface. A direct file:// view is not authoritative: root-relative styles, token reloads, and source-backed tool endpoints require the local HTTP server and can look stale or incomplete without it.
Archive publication layersRecord, version, state, material, and documentation visibility are independent gates. A public state lead must belong to that state and its Digital asset must already be active, public, inline, and consent-granted or consent-not-required. Save shared asset eligibility before publishing the material.
Tiny colored labelsA saturated source color is not automatically legible as small type. Use a solid badge for merch/source labels, with the token color as fill and a computed or chosen readable ink color.
Push policyNever push. The user pushes manually. Work directly on main.
